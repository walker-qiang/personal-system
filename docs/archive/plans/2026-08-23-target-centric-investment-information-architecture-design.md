# 标的优先的投研信息架构设计

> 状态：已确认设计
>
> 日期：2026-08-23
>
> 范围：`personal-system`、`personal-assets`、`personal-os`

## 1. 决策

`personal-assets/13-财富/投研/标的/<target_id>/` 是单个投资标的长期信息的权威聚合目录。

标的级 profile、官方报告、研究卡、收益分析、估值历史和重要事件应按标的归档。观察池、同业比较、基金目录、组合复盘、模板和投资政策等跨标的内容继续保留在外层。

App 的全局研究列表、消息、搜索、日期视图和比较视图由 `personal-os` 从 Vault 构建 SQLite/cache 投影，不通过复制 durable 文件实现。

## 2. 目标结构

```text
13-财富/投研/
  标的/
    <target_id>/
      profile.yaml
      reports/
      research/
      return-analysis/
      valuation/
      events/

  观察池/
  同业/
  基金池/
  复盘/
  90-模板/
```

子目录职责：

- `profile.yaml`：标的稳定身份、市场、币种和基础 profile。
- `reports/`：官方报告、公告和已完成对账的事实。
- `research/`：针对该标的的历次研究卡和复查结论。
- `return-analysis/`：经用户确认需要长期保留的收益分析快照。
- `valuation/`：该标的的长期估值记录。
- `events/`：需要长期追踪的重要公司行为和市场事件。

## 3. 稳定身份

目录必须使用稳定 `target_id`，不能使用可能变化的名称：

- A 股：`sh600519`、`sz000568`。
- 港股：`hk00700`。
- 其他上市标的：使用规范化市场代码。
- 无公开市场代码的基金、理财或其他对象：使用注册表中的稳定 ID 或带命名空间的代码。

标的改名不改变目录；代码迁移、合并或退市通过 profile 和事件记录表达，不能直接以新名称重建目录。

## 4. 内容边界

以下内容不放入单个标的目录：

- 观察池和候选池；
- 同业组与跨公司比较；
- 基金池或产品注册表；
- 组合级复盘、调仓决策和投资政策；
- 模板；
- 自动任务、审批、日志和其他运行态。

跨标的文档可以引用多个 `target_id`。App 通过索引反向展示“与该标的相关的观察池、复盘和决策”，不复制原文件。

## 5. 收益分析历史

收益分析采用两层保存：

1. 每次成功计算自动保存到本地 `var/history/return-analysis.sqlite`。
2. 完全相同的规范化输入使用请求 hash 去重，只更新时间和计算次数。
3. 用户固定结果、研究卡引用结果、投资决策引用结果或季度复盘确认结果时，保存到：

```text
13-财富/投研/标的/<target_id>/return-analysis/<date>-<record_id>.yaml
```

SQLite 是近期历史和产品体验，不是 durable source of truth。进入 `personal-assets` 的记录必须保存规范化输入、实际计算区间、数据源、输入 hash、复权口径、算法版本和完整结果。

## 6. 读取与写入

迁移期间遵循：

```text
读取：旧路径 + 新路径
写入：只写新路径
```

禁止把同一研究卡、估值或收益分析同时写入新旧目录。全局视图由 cache 聚合，不维护第二份 durable 索引文件。

所有产品写入继续经过 `personal-os` 的 operation-specific API 和 AssetStore。客户端、Agent 和脚本不得自行拼接 Vault 路径。

## 7. 记录身份与链接

现有研究卡 ID 曾部分依赖相对文件路径；在本次迁移前已完成记录身份解耦：

- 新记录使用显式稳定 `record_id`。
- 旧记录保留原 ID 或记录 `legacy_id` 映射。
- App 消息、历史展开、API 回读和研究比较使用稳定 ID，不使用路径作为业务身份。
- 文件路径仍作为 provenance 返回，但移动文件不能改变记录身份。

该前置条件已满足。迁移阶段曾将 8 张 schema v2 研究卡按 `subject.code`
迁移到标的目录，并保留旧记录的 `legacy_id` 和历史链接；后续新增记录直接
使用服务端生成的稳定 `record_id`。这 8 张历史卡后来在 2026-08-30 的 A 股
质量观察池重建提交 `87622d8` 中被清理，当前存量以 `personal-assets` 工作树
为准，代码仍保留旧平铺路径的兼容读取能力。

## 8. 估值快照

当前 `13-财富/投研/估值快照/YYYY/MM/` 是按批次和日期生成的多标的结果。它与标的优先结构存在不同聚合轴，不能直接复制成两份权威数据。

迁移估值前需要单独确认：

- 单标的 `valuation/` 是否成为权威源；
- 日期批次是否只保留运行清单或由 cache 动态生成；
- 历史估值记录的幂等键和修正方式。

因此估值快照最后迁移，不阻塞 profile、reports、research 和 return-analysis 先进入标的目录。

## 9. 分阶段迁移

### Phase 1：读取抽象和稳定 ID

- 研究卡读取支持旧平铺目录与新标的目录。
- 新研究卡写入 `标的/<target_id>/research/`。
- 引入稳定 `record_id`，保持现有历史链接可用。

当前状态（2026-08-31）：迁移阶段为历史旧卡注入显式 `record_id`；后续新研究卡
由服务端生成显式 `record_id`。标的详情、消息中心和 Agent research context 已
切换为双路径读取，新写入只进入标的目录；当前存量以 `personal-assets` 工作树
为准。

### Phase 2：收益分析历史

- 建立本地自动历史 SQLite。
- 增加历史展示、重新测算和删除。
- 增加显式固定到 Vault 的受控操作。

当前状态（2026-08-23）：本地自动历史、request hash 去重、详情、重新测算、删除和市场测算固定到 Vault 已完成；固定结果写入标的 `return-analysis/`。

### Phase 3：研究卡迁移

- 按 `subject.code` 将旧研究卡移动到对应标的目录。
- 保持 Git 历史、frontmatter、稳定 ID 和来源字段。
- 校验全局列表、消息、历史对比和 Agent research context。

当前状态（2026-08-31）：迁移动作已于 2026-08-23 完成，commit `47cd12a`；
当时 8 张 schema v2 研究卡迁移到 4 个标的目录且 legacy `record_id` 全部保留。
后续 2026-08-30 的 A 股质量观察池重建提交 `87622d8` 清理了这批历史卡；当前
旧 `研究/` 目录仅剩 2 份跨标的系统设计文档，现存研究卡以工作树为准。

### Phase 4：估值与事件

- 明确估值权威模型后迁移。
- 增加事件记录并接入标的详情投影。
- 旧平铺目录在完成验收后停止读取。

## 10. 验收条件

- 同一标的的 profile、报告、研究卡和收益快照可以从一个目录完整定位。
- 全局研究、消息、搜索和观察池页面行为不退化。
- 同一 durable 内容不存在新旧两份权威副本。
- 移动研究卡不改变稳定记录 ID。
- `personal-os` 删除本地 cache 后可以从 Vault 重建全局视图。
- 回滚时可以恢复旧读取优先级，不需要反向复制新文件。
